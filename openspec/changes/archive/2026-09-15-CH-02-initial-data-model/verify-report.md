## Scope conformance

- No tenant lifecycle/isolation code (alta, baja, listado, filtrado por request) — confirmed by inspecting the models: `Tenant` has no soft-delete field, no application route reads or writes it beyond the seed script. Matches proposal.md's "Out of Scope" (T1/T2/T4 remain CH-06).
- `Conexion.credencial` is a plain, unencrypted `String` — confirmed by schema inspection; no encryption logic exists anywhere in this change. Matches proposal.md (A2 remains R1).
- No `ejecucion`, `usuario`, `plantilla`, `automatizacion`, or `mapeo` model or table — confirmed above (Requirement 4).
- `Conexion.motor` is `String`, not an enum — confirmed by schema inspection. D-4 stays open, not resolved by this change.

## Deviations from design.md found and corrected during apply

1. `prisma/seed.ts` originally imported the generated Prisma client from `src/generated/prisma/client.js` per the initial design; the runtime Docker image (built in CH-01) never copies `src/`, only `dist/`. Found when the `app` container crashed with `ERR_MODULE_NOT_FOUND` on first real bring-up. Fixed by importing from `dist/generated/prisma/client.js` instead, and `design.md` was amended in place with a dated note.
2. The migration file itself was generated by running `prisma migrate dev` on the host against a temporarily port-exposed `db` container, not inside a throwaway Docker container as first attempted — two container-based attempts either lost the generated file (`--rm` removing the writable layer) or silently failed to bind-mount to the host. Documented in `design.md`'s "Migration generation environment note"; the temporary port mapping was reverted from `docker-compose.yml` immediately after, and the generated `prisma/migrations/` folder is a normal committed artifact from that point on — no trace of the workaround remains in the shipped Compose file.

Neither deviation changes what the spec requires — both are implementation-detail corrections, already reflected in the current `design.md`/code.

## Non-negotiable rules (docs/00-contexto.md §5)

- Rule 5 (minimización de datos): confirmed by schema inspection — neither `Conexion` nor `ConsultaGuardada` stores personal data of a tenant's own customers.

The temporary `db` port exposure used only during migration generation (see deviation 2) carried no secret beyond the already-placeholder `.env` value, and was reverted before this report was written.
- No other rule newly engaged by this change.
