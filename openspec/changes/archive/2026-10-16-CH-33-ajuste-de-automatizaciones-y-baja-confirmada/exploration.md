# Exploration: CH-33 — Adjusting an automation from the console, and a typed confirmation for a tenant's baja

Status: **decided** (2026-10-14): D1 (a) the same as the alta, D2 (a) the recipient can be cleared. No research phase. Store: openspec. Origin: the audit of 2026-10-13 (`docs/auditoria-2026-10-13.md`, §3.4, §4.5, phase F3) and the two product decisions taken on 2026-10-14: DEC-174 (the console adjusts an automation in place, like the panel) and DEC-175 (a tenant's baja requires typing its name, in the console and in the API). Front end and back end: one new route, one changed route contract, no migration.

## Shape that fits (no decision needed)

- **Route.** `PUT /automatizaciones/:id/ajustes`, mirroring the panel's path, scoped by `X-Tenant-Id` (not exempt). Strict body with `propertyNames` over the editable keys only, so `plantillaId`, `conexionId`, `activo` or `tenantId` are a `400`. Read first through the scoped model: unknown or foreign id `404 automatizacion-no-encontrada`; inactive `409 automatizacion-desactivada` (the operator's word, DEC-79; the panel's `automatizacion-pausada` is client copy). One scoped `update` of the changed columns; response = `AutomatizacionCompleta` + `proximaEjecucion` + `zonaHoraria`, like the alta. Empty body `400`. The scheduler re-reads `cron` and `valores` every tick: no reprogramming.
- **Validation is the alta's.** Pure checks first (`cronValido`, `destinatarioDe` + `direccionValida`), then `prepararSentencia(sanearSql(plantilla.sql), plantilla.parametros, valores)` on the template of the stored row. These are the same functions `resolverAjustes` calls underneath; the panel's four-field resolver itself does not fit the operator (see D1).
- **Console form.** «Ajustar» per active row, next to «Desactivar». A pop-up `#auto-ajuste` (DEC-173) titled with the template and connection names, prefilled from `GET /automatizaciones/:id`: one input per declared parameter, the frequency/hour/cron trio (a preset cron opens on its preset, any other on «Personalizado»), and the recipient. Template and connection shown as read-only text. «Guardar ajustes» + «Cancelar»; dirty = any field differs from what was loaded. On `200`: close, page notice with the next run, reload the list. `400` / `409` stay inside the pop-up. Copy that says «no se puede editar» / «no se puede cambiar después» is rewritten.
- **Baja, API.** Body `{ nombre }`, strict schema (`propertyNames`, `required`). Missing or extra key: `400 solicitud-invalida`. Order: schema, then read (`404`, `409 tenant-desactivado`), then compare `nombre` with the stored name, **exactly** (no trim, no case folding): mismatch `409 confirmacion-no-coincide`, nothing written. Unknown id still answers `404` before the name is compared, so the name check reveals nothing new.
- **Baja, console.** «Dar de baja» opens a pop-up `#tenant-baja` naming the tenant, saying it cannot be undone (the agent sockets close, every scoped call answers 409), with one text field and «Dar de baja {nombre}» disabled until the field equals the name exactly. «Cancelar» and Escape close without sending; nothing typed counts as no changes (closing a confirmation never asks «Descartar cambios»). The request sends `{ nombre }` with the typed value. Replaces the inline confirmation (DEC-175 exception to DEC-173's last bullet).
- **Specs.** Modify `automation-scheduling` "Automation Lifecycle…" (adds the adjust route, removes the "no PUT" scenario), `tenant-management` "Logical Deactivation…" (typed name), `query-console` (automations: adjust; tenants: baja pop-up; guarded ids). `docs/02-mapa-de-changes.md` gains the CH-33 row. `scripts/smoke.sh` sends the name.
- **Out of scope.** Changing template or connection, reactivating an automation, template → saved query (audit §3.2, still open), CH-30e screens, the panel (unchanged).

## Decisions (resolved 2026-10-14)

- **D1 — What the console edits in `valores` and `cron`.** DEC-174 says "the same fields as the panel" and "reuses panel-ajustes validation", but the panel only edits `umbral` and a preset schedule, while the operator's wizard sets every declared parameter and accepts a custom cron.
  - (a) **The same as the alta** (recommended): every declared parameter, any valid cron (presets or «Personalizado»), recipient. Validation with the alta's functions, which `panel-ajustes` also uses underneath. DEC-174's wording is amended to say so.
  - (b) **Exactly the panel's four fields**: `umbral`, `hora` + `dias` over a preset cron, `destinatario`, reusing `resolverAjustes` verbatim. A custom cron or any other parameter cannot be edited from the console; a template without `umbral` can only change schedule and recipient.
- **D2 — Clearing the recipient.** The alta allows no recipient (no email sent, `sin-destinatario`); the panel cannot clear it.
  - (a) **Can be cleared** (recommended): an empty field sends `destinatario: null`, the row stops notifying. Symmetric with the alta.
  - (b) **Cannot be cleared**, as in the panel: an empty field leaves it as it was. To stop notifying, deactivate.

| Risk | Likelihood | Mitigation |
